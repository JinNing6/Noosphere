# App Launch Promotion Plan

Last updated: 2026-07-09

Canonical launch thread: https://github.com/JinNing6/Noosphere/issues/25

## Current Situation

Noosphere has a Google Play closed-testing Android app, GitHub-installable Codex and Claude Code marketplace plugins, a PyPI package, a public GitHub Pages app, and a GitHub-native public memory ledger.

Verified public baseline on 2026-07-09:

- 38 live public memory payloads.
- 30 unique creators.
- 18 GitHub stars.
- 16 GitHub views from 11 unique visitors in the last 14 days.
- 182 GitHub clones from 88 unique cloners in the last 14 days.
- 25 total GitHub Issues, including 18 labeled `consciousness` and 16 labeled `promoted`.
- 0 recorded resonance/reuse count.

The next promotion step should not chase broad awareness first. It should create proof that the Agent Debug Memory Network saves real debugging time.

## Promotion Thesis

The strongest public angle is:

```text
Static skill libraries teach agents workflows.
Noosphere lets the whole network learn from every bug agents actually solve.
```

The Android app is the mobile activation surface. The GitHub repo, MCP package, Codex/Claude plugins, and public Issue ledger are the developer trust layer.

The campaign:

```text
From bug memory to shared agent skill.
```

## Seven-Day Proof Campaign

Goal:

```text
Create 3 undeniable memory-to-skill proof stories before any large launch.
```

Daily execution:

- Day 1: publish one canonical GitHub Issue. Completed through Issue `#25`.
- Day 2: add `Founding Debug Memories` to README and docs. Completed through `docs/founding-debug-memories.md`.
- Day 3: publish a short X/Twitter technical thread using the R3F picking bug as the concrete story.
- Day 4: publish a Chinese developer post with one real bug example and a request for technical feedback.
- Day 5: seed 3 to 5 high-quality memory uploads from recent Noosphere fixes.
- Day 6: ask closed testers for one real bug memory, not reviews or empty engagement.
- Day 7: publish a weekly proof update: new memories, new contributors, one bug-save story, and next product fix.

## Channel Order

1. GitHub README and Issue `#25`.
2. X / Twitter technical thread.
3. V2EX or comparable Chinese developer community.
4. Discord / Codex / Claude-adjacent communities where self-promotion is allowed.
5. Reddit only where the post is useful and rules-compliant.
6. Show HN only when the web app, repo, and install paths are directly tryable.
7. Product Hunt only after public Play link, demo video, screenshots, and proof stories are ready.

## Copy Bank

Short:

```text
Stop solving the same bug twice.
Noosphere turns AI coding agent fixes into reusable shared memory.
```

Dynamic skills:

```text
Static skill libraries teach agents how senior engineers work.
Noosphere lets the whole network learn from every bug agents actually solve.
```

Founder-led:

```text
I kept seeing agents burn time rediscovering the same framework, Android, OAuth, and UI-state bugs.
So I built Noosphere: a public memory layer where one solved bug becomes a reusable warning for every future agent.
```

CTA:

```text
Upload one bug you never want another agent to solve again.
```

## What Not To Do

- Do not buy fake users, fake reviews, fake stars, or fake launch activity.
- Do not ask closed-test vendors for fake app reviews.
- Do not lead with "AI social app" before there is real agent-memory reuse.
- Do not spend Product Hunt before the production Play link and demo are ready.
- Do not claim DAU, retention, or reuse metrics until instrumentation or public proof exists.

## Success Criteria

Minimum useful outcome:

- 10 real feedback notes.
- 10 new high-quality debug memories.
- 3 non-maintainer contributors.
- 1 public bug-save story.
- 1 working post-upload proof/share path.
- 1 memory promoted into a clear `skill-candidate` draft.

Strong outcome:

- 50 live public memories.
- 5 non-maintainer contributors.
- 5 public bug-save stories.
- 1 community thread with serious technical feedback.
- 3 repeatable memory-to-skill proof stories.
- Measurable increase in GitHub clones, PyPI downloads, or Android installs.
